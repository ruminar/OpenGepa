# OpenGepa v0.1 仕様書

## 1. 概要

OpenGepaは、Windowsのタスクトレイに常駐する個人向けランチャーアプリである。

目的は次のとおりとする。

- Windows標準スタートメニューでは不足する個人整理機能を提供する
- アプリ、ファイル、ディレクトリ、Webページを同じ小さなウインドウから起動できるようにする
- 複数のランチャーを右側の縦タブで切り替えられるようにする
- ユーザー自身が育てられる作業入口を提供する
- 設定とアイコンを含めて保存し、別の場所や別PCへ移行できるようにする

OpenGepaは汎用ウィジェットアプリではなく、タスクトレイから即座に呼び出せるランチャーを中心とする。

---

## 2. 開発方針

### 2.1 技術

- C#
- .NET 10
- WPF
- MVVM構成

### 2.2 対応環境と配布形式

- 対応OSはWindows 11 x64とする
- 発行RIDは`win-x64`とする
- .NET 10のフレームワーク依存型（framework-dependent）として発行する
- 単一EXEにはせず、発行ディレクトリ全体をZIP化して配布する
- 利用者は.NET 10 Windows Desktop Runtime x64を事前にインストールする
- ZIPを展開したディレクトリ内で、実行ファイル、設定、アイコンをまとめて管理する

### 2.3 基本方針

- WindowsデスクトップUIとの親和性を優先する
- ランチャーの階層表示にはWPFのTreeViewを使用する
- ツリーは任意深度とする
- タスクトレイ常駐、DPIスケーリング、右クリックメニュー、ドラッグ＆ドロップに対応する
- 表示モデル、永続化モデル、UIを分離する
- 未実装の将来機能を画面上に無効項目として露出させない
- ポータブルなZIP配布を前提とする

- タスクトレイ常駐

- アイコンのPNGキャッシュ

- OpenGepa Profile（`.ogp`）のSave／Load
- Windows自動起動設定

## 4. 用語とデータモデル

### 4.1 LauncherTab

右側縦タブに表示する、独立したランチャー単位である。

各LauncherTabは次の情報を持つ。

- 一意な内部ID
- 表示名
- アイコンパス（任意）
- 表示／非表示
- 表示順
- ルート直下のLauncherNode一覧

v0.1ではLauncherTabの種類はアプリランチャーのみとする。将来、WindowsメニューやWebショートカット専用タブを追加できる設計余地を残す。

### 4.2 LauncherNode

TreeView上の共通要素である。

```text
LauncherNode
├ Group
└ LauncherItem
   ├ FileItem
   ├ DirectoryItem
   └ UrlItem
```

共通情報は次のとおりとする。

- 一意な内部ID
- 表示名
- 表示順
- アイコンパス（任意）

### 4.3 Group

Groupは整理用のコンテナであり、起動対象ではない。

- 子としてGroupまたはLauncherItemを保持できる
- Groupの中へGroupを作成できる
- 任意深度を許可する
- 展開／折り畳みに対応する
- 自分自身または自分の子孫を子にすることはできない

### 4.4 LauncherItem

LauncherItemは起動可能な末端要素であり、子を持たない。

#### FileItem

Windows上のファイルを開く項目である。

例:

- `.exe`
- `.lnk`
- `.bat`
- `.cmd`
- `.ps1`
- 文書
- 画像
- 音声・動画
- その他、Windowsに関連付けられたファイル

#### DirectoryItem

ローカルディレクトリまたはUNCネットワークディレクトリをエクスプローラーで開く項目である。

`DirectoryItem`は表示名を持たず、JSONにも`name`を保存しない。`target`のフルパスを表示名として扱う。追加・編集時はtargetだけを入力し、名前変更メニューは表示しない。

#### UrlItem

HTTPまたはHTTPSのURLをWindows既定ブラウザで開く項目である。

### 4.5 ルート

LauncherTabのルート直下にはGroupとLauncherItemの両方を配置できる。ルートは名前を持たない仮想Groupと同じ重複規則を使用する。

### 4.6 Separator

ユーザーがTreeViewへ配置する区切り線はv0.1では実装しない。Group、表示順、余白だけで操作感を確認し、必要性が確認できた場合に将来追加する。

右クリックメニュー内の一般的な視覚上の区切り線は使用してよい。

## 5. 名前の規則

### 5.1 同一階層内の一意性

同一Group直下では、GroupとLauncherItemの種類をまたいで表示名を一意とする。ルート直下にも同じ規則を適用する。

異なるGroup間では同名を許可する。LauncherTabの表示名もLauncherTab間で一意とする。

### 5.2 比較方法

名前の比較キーは次の順序で生成する。

1. 前後を`Trim()`する
2. Unicode NFC（Normalization Form C）へ正規化する
3. `OrdinalIgnoreCase`で比較する

次の名前は同名として扱う。

```text
Chrome
chrome
CHROME
 Chrome
Chrome 
```

次の変換は行わない。

- 全角・半角の統一
- 内部の連続空白の統一
- 表示名の小文字化

保存する表示名は、前後の空白を除去してNFCへ正規化したものとする。入力された大文字・小文字は維持する。

### 5.3 禁止する名前

- 空文字
- 空白だけの名前
- 改行を含む名前
- 制御文字を含む名前

通常の日本語、記号、絵文字は許可する。

### 5.4 重複時の動作

追加、名前変更、内部移動、外部ドロップ、Profile Loadの各処理では、適用前に重複を検証する。

- 自動で`(2)`などへ改名しない
- 競合する操作は適用しない
- ユーザーに競合する名前と場所を表示する

## 6. アプリケーションのライフサイクル

### 6.1 起動

- 通常起動時は画面を表示せず、タスクトレイへ常駐する
- Windows自動起動時も画面を表示せず、タスクトレイへ常駐する
- 二重起動を禁止する
- 二重起動された場合、新しいプロセスは終了し、既存プロセスのランチャーウインドウを表示する

### 6.2 トレイアイコンの左クリック

- 起動専用ランチャーウインドウの表示／非表示を切り替える
- 表示中に再クリックした場合は非表示にする
- ウインドウ外をクリックした場合は非表示にする
- `Esc`キーで非表示にする
- 項目の起動要求に成功した場合は非表示にする
- 起動に失敗した場合は表示を維持する
- ランチャーウインドウはタスクバーに表示しない
- ピン止め中は、項目起動成功、設定表示、フォーカス喪失で非表示にしない。ピン状態は保存する
- ピン状態に関係なく、閉じるボタンはランチャーを非表示にする

### 6.3 トレイアイコンの右クリック

次のコンテキストメニューを表示する。

```text
設定
----------------
終了
```

- 設定: 設定ウインドウを開く
- 終了: OpenGepaを終了する

### 6.4 ウインドウを閉じる操作

次の操作ではOpenGepaを終了せず、対象ウインドウを閉じてタスクトレイへ戻す。

- 閉じるボタン
- 最小化
- `Alt+F4`
- タスクバーからの「ウインドウを閉じる」

アプリケーションを終了できる通常のUI操作は、トレイ右クリックメニューの「終了」のみとする。

Windowsのシャットダウンまたはサインアウト時は、OSの終了要求に従って正常終了する。

### 6.5 終了処理

- 確定済みデータの保存完了を確認する
- トレイアイコンを破棄する
- 一時ファイルとリソースを閉じる
- 正常にプロセスを終了する

## 7. ランチャーウインドウ

### 7.1 構成

0.1.0では480×600 DIPの固定サイズとし、ユーザーによるサイズ変更を許可しない。

- トレイクリック時のマウスポインターが存在するモニターへ表示する
- ウインドウ全体が対象モニターの作業領域内へ収まるよう表示位置を補正する
- マルチモニターと、上下左右いずれのタスクバー配置にも対応する

```text
+--------------------------------------+--------+
|                                      | 開発   |
|                                      +--------+
|                                      | AI     |
|       選択中LauncherTabのTreeView     +--------+
|                                      | 管理   |
|                                      +--------+
|                                      |        |
+--------------------------------------+--------+
```

左側を選択中LauncherTabのメイン領域、右側を縦タブ領域とする。

### 7.2 Dashboard／Header

将来Dashboard／Headerを配置できるコンテナを内部的に用意する。v0.1ではコンテンツを持たず、領域を折り畳んで表示しない。

日付、時計、カレンダーなどのDashboard機能はv0.1対象外とする。

### 7.3 縦タブ

- v0.1ではアプリランチャーのLauncherTabだけを表示する
- 複数のLauncherTabを作成できる
- 初回起動時は既定のLauncherTabを一つ作成する
- 左クリックでLauncherTabを切り替える
- 最後に選択した表示中のLauncherTab IDを保存する
- 次回表示時に前回選択タブを復元する
- 対象タブが削除済みまたは非表示なら、表示中の先頭タブへフォールバックする
- タブの表示／非表示を切り替えられる
- 非表示にしてもデータを削除しない
- すべてのタブを非表示にすることを許可する
- 表示中タブがない、またはApp Launcherが0件の場合も、右側の縦タブ領域の空白部を右クリックして「設定」または「ランチャーの新規登録」を実行できる

v0.1ではタブ自体のドラッグ＆ドロップによる並べ替えを実装しない。表示順変更が必要な場合は設定画面の上下操作を使用する。

### 7.4 縦タブの右クリック

LauncherTab上では次のメニューを表示する。

```text
このランチャーを編集
このランチャーを複製
----------------
名前を変更
アイコンを変更
アイコンを標準に戻す
----------------
非表示にする
削除
```

- 右クリックされたタブを選択せず、左側に現在表示中のApp Launcherを維持したままメニューを表示する
- 「このランチャーを編集」で対象の編集画面を開く
- 複製はツリー構造、項目、表示順、アイコン参照を複製する。ただしLauncherTabとLauncherNodeの内部IDは新しく発行する
- 複製名は末尾の` (番号)`を除いた元名に` (2)`、` (3)`を付加し、既存LauncherTabと重複しない最初の番号とする。たとえば`Launcher (2)`を複製し、`Launcher`と`Launcher (2)`が存在する場合は`Launcher (3)`とする
- アイコン変更と標準への復帰を実行できる
- 削除時は種別と名前を表示して確認する。v0.1の種別は`App Launcher`である
- 「設定」と「ランチャーの新規登録」を表示する
- 縦タブ領域の空白部では「設定」と「ランチャーの新規登録」だけを表示する

縦タブ領域の空白では次のメニューを表示する。

```text
新しいランチャーを作成
タブの管理
```

### 7.5 検索、ピン止め、TreeViewの起動操作

- ランチャー上部の検索欄は、現在のApp Launcher内の表示名を部分一致・大文字小文字を区別せず絞り込む
- 一致する子孫を持つGroupは到達経路として残し、検索中は該当Groupを展開する
- 検索を空にすると、元の展開状態を復元する
- ピン止め中はランチャーを自動で隠さず、最前面表示は無効にする。固定状態は通常時・ホバー時とも見分けられる色で表示する
- 起動画面の右クリックでも、追加、名前変更、target変更、アイコン操作、削除を行える。FileItemはWindows標準のプロパティ画面を開ける

- Groupのシングルクリックで展開／折り畳みを切り替える
- FileItem、DirectoryItem、UrlItemごとに、設定画面からシングルクリックまたはダブルクリックでの起動を選択できる
- 初期値はFileItemがシングルクリック、DirectoryItemとUrlItemがダブルクリックである
- 選択したクリック回数と一致したときだけ対象を起動し、二重起動しない
- キーボード選択後の`Enter`でLauncherItemを起動し、Groupは展開／折り畳みを切り替える
- Groupをキーボード選択中の`Space`で展開／折り畳みを切り替える
- LauncherItemの起動要求に成功した場合だけランチャーウインドウを閉じる

## 8. 編集ウインドウ

### 8.1 基本動作

- 縦タブ右クリックの「このランチャーを編集」から開く
- 固定された通常ウインドウとして表示する
- タスクバーに表示する
- フォーカスを失っても閉じない
- 編集ウインドウはLauncherTabごとに一つだけ作成する
- 別のLauncherTabの編集画面は同時に開ける。同じLauncherTabを再度開く場合は既存ウインドウを前面へ出す
- 閉じる、最小化、`Alt+F4`ではOpenGepaを終了しない

### 8.2 即時反映と即時保存

編集ウインドウ全体の「適用」または「保存」ボタンは設けない。

次の確定操作ごとに変更を検証し、即時保存する。

- 追加ダイアログの「OK」
- 編集ダイアログの「OK」
- 名前変更の確定
- 削除確認の「削除」
- 内部ドラッグ＆ドロップの完了
- 外部ドロップの登録確定
- ディレクトリ走査結果の登録確定
- アイコン変更の確定
- 表示順または親Group変更の確定

別のLauncherTabの編集ウインドウへもGroupまたはLauncherItemをドラッグ＆ドロップできる。移動は一つの検証・保存操作として扱い、移動元と移動先を同時に更新する。

テキスト入力中の一文字ごとには保存しない。

保存成功後にランチャー表示へ反映する。保存に失敗した場合は変更を確定せず、元の状態を維持してエラーを表示する。

### 8.3 Undo／Redo

v0.1ではUndo／Redoを実装しない。

- `Ctrl+Z`および`Ctrl+Y`によるツリー編集の復元は行わない
- 削除は必ず確認後に実行する

### 8.4 TreeViewの右クリック

編集TreeViewは、保存データには含めない仮想の`root`ノードを最上位に表示する。`root`は常に展開状態とし、ルート直下の項目を明示して操作するためのUI要素である。

`root`では次の操作を提供する。

```text
グループを追加
ファイルを追加
Directory参照追加（UNC可）
URLを追加
フォルダを走査して一括登録
```

Groupでは次の操作を提供する。

```text
グループを追加
ファイルを追加
Directory参照追加（UNC可）
URLを追加
フォルダを走査して一括登録
----------------
名前を変更
アイコンを変更
アイコンを標準に戻す
----------------
削除
```

LauncherItemでは次の操作を提供する。

```text
名前を変更
起動対象を変更（FileItem）
開く場所を変更（DirectoryItem）
URLを変更（UrlItem）
----------------
アイコンを変更
アイコンを再取得（FileItem）
アイコンを標準に戻す
----------------
削除
```

名前変更、対象変更、アイコン操作は一項目を選択している場合だけ実行できる。複数選択時の右クリックは選択状態を維持し、「削除」で選択項目を一括削除できる。追加とアイコン操作の編集画面上部ボタンは設けない。

編集画面上部のGroup、File、Directory、URL追加では、確認ダイアログに登録先をルートからの階層パスで表示する。登録先はプルダウンからルートまたは任意のGroupへ変更できる。選択中のGroupを初期値とし、LauncherItemを選択中ならその親Groupを初期値とする。

File追加のファイル選択ダイアログは、既定で次の拡張子フィルターを提供し、`*.*`による無制限の選択肢は表示しない。

- プログラムとショートカット: `.exe`、`.lnk`、`.bat`、`.cmd`、`.ps1`
- 文書: `.pdf`、`.txt`、`.rtf`、`.csv`、Office文書
- 画像: PNG、JPEG、BMP、GIF、WebP、ICO
- 音声・動画: MP3、WAV、FLAC、M4A、MP4、MKV、AVI、WMV、MOV

### 8.5 削除

- `Delete`キーまたは右クリックメニューの「削除」で確認を表示する
- TreeViewが項目フォーカスを持ち、項目が選択されている場合だけ`Delete`キーを項目削除に使用する
- テキスト入力中の`Delete`キーでは項目を削除しない
- v0.1の編集TreeViewは複数選択に対応する
- `Shift`＋クリックで表示中のアンカー項目からクリック項目までを範囲選択する
- `Ctrl`＋クリックで個別項目の選択を追加または解除する
- 複数選択中の`Delete`キーまたは「削除」は、選択項目を一回の確認と一回の保存で一括削除する
- 削除や編集による再描画後も、存在するGroupの展開／折り畳み状態を内部IDで復元する
- キャンセル時は何も変更しない
- 確認後に削除し、即時保存する

LauncherItemの確認例:

```text
「Chrome」を削除しますか？
この操作は元に戻せません。
```

Groupの確認では、直下だけでなく全子孫の件数を表示する。

```text
「開発」と、その中にある12件の項目を削除しますか？
この操作は元に戻せません。
```

### 8.6 内部ドラッグ＆ドロップ

次の操作に対応する。

- 同じGroup内での並べ替え
- 別Groupへの移動
- ルートへの移動
- Group内へのGroup移動
- Group内へのLauncherItem移動

次の操作を拒否する。

- Groupを自分自身へ移動
- Groupを自分の子孫へ移動
- 移動先で名前が重複する移動
- LauncherItemの中へ別要素を移動

ドロップ位置を視覚的に区別する。

- 項目の上側: その項目の前へ挿入
- 項目の下側: その項目の後ろへ挿入
- Groupの中央: Groupの子として挿入
- ルート空白部分: ルートへ挿入

移動可能であることを検証してから、元の位置から削除する。

### 8.7 Explorerからのドラッグ＆ドロップ

編集ウインドウのTreeViewへ、Windows Explorerからファイルとディレクトリをドロップできる。

- ファイルはFileItemとして登録する
- ディレクトリは「DirectoryItemとして登録」または「中身を走査して一括登録」を選択できる
- Group上へのドロップはそのGroupを登録先とする
- 項目間へのドロップはその位置を登録先とする
- 空白部分へのドロップはルートを登録先とする
- 「項目を追加」ダイアログには登録先をルートからの階層パスで表示する
- 登録先は同ダイアログのプルダウンからルートまたは任意のGroupへ変更できる
- 複数項目を一括登録できる
- 登録前に全項目を検証する
- 名前衝突を自動改名しない
- 一部だけ登録して残りを失敗させない

### 8.8 ディレクトリ走査による一括登録

初期設定の負担を減らすため、指定ディレクトリを再帰的に走査し、複数のFileItemを作成できる。

- 走査はUIスレッドをブロックしないバックグラウンド処理とする
- 走査中は進捗と検出件数を表示する
- 走査中は常にキャンセル可能とする
- 実ディレクトリ階層をGroup階層として再現する
- 登録前にプレビューを表示する
- ユーザーが登録対象を選択できる
- 登録先として現在のLauncherTab内にある任意のGroupまたはルートを選択できる
- 走査元ディレクトリ自体を登録先直下のGroupとして作成し、その下に実ディレクトリ構造を再現する
- 登録先直下に走査元と同名のGroupが存在する場合は、そのGroupを再利用して中身を展開する
- 走査元と同名のGroup以外の項目が登録先直下に存在する場合は、競合として登録を拒否する
- `.exe`と`.lnk`は初期選択状態とする
- ただし、インストーラー候補と32bit版候補は初期未選択とし、ユーザーが必要なものだけ再選択できるようにする
- インストーラー候補は`setup`、`install`、`installer`、`uninstall`系のファイル名で判定する
- 32bit版候補は`x86`、`x32`、`win32`、`32bit`、`ia32`、`i386`のパス要素またはファイル名表記と、ファイル名末尾の`32`または`32L`で判定する
- `.bat`、`.cmd`、`.ps1`は候補に表示するが初期未選択とする
- 文書、画像、音声、動画などは既定の自動候補に含めない
- 隠し・システムディレクトリは既定で除外する
- ジャンクションおよびシンボリックリンクを再帰追跡しない
- アクセス拒否や読み込み不能な場所は読み飛ばし、完了時に件数を表示する
- 走査中はアイコンを抽出せず、登録対象として選択された項目だけ登録確定時に抽出する
- 登録確定後のアイコン取得とJSON検証／保存中は、処理件数と現在の対象を示す進捗バーを表示する
- 選択項目からアイコンを取得できなくても一括登録全体を失敗させず、その項目のJSONではアイコンを未指定とする
- アイコン未指定の項目にはOpenGepa内蔵の標準アイコンを表示し、完了時にアイコン取得失敗件数を報告する
- 名前衝突はプレビュー上で解消してから登録する
- 名前衝突または登録先衝突のある候補行は背景を黄色で表示し、エラー対象を一覧上で特定できるようにする
- 登録確定時に、対象ファイル、登録先、名前重複、Group構造を再検証する
- 全体の検証成功後、一回の確定操作として登録・保存する
- ディレクトリ走査から作成するFileItemの初期表示名には拡張子を含める

走査には次の安全上限を設ける。

- 検出候補: 10,000件
- 確認するファイルとディレクトリの合計: 100,000件
- Groupの階層深度: 256

いずれかの上限へ到達した場合は走査を中止し、不完全な途中結果を登録させず、より小さいディレクトリを選択するよう案内する。

#### 8.8.1 大規模ディレクトリの警告

次を走査元として指定した場合は、走査開始前に警告を表示する。

- ドライブのルート（例: `C:\`、`D:\`）
- 現在のWindows環境におけるProgram Filesディレクトリ
- 現在のWindows環境におけるProgram Files (x86)ディレクトリ

パスは絶対パスへ正規化し、末尾の区切りと大文字・小文字の違いを無視して判定する。Program Files配下の個別アプリケーションディレクトリは、この特別警告の対象にしない。

警告例:

```text
選択されたディレクトリには非常に多くのファイルが含まれる可能性があります。
走査には時間がかかる場合があります。

Program Filesに登録されたアプリケーションは、将来対応予定のWindows Menuから利用できるようにする予定です。

このディレクトリの走査を続行しますか？

［続行 (Y)］［キャンセル (N)］
```

- 既定選択は「キャンセル (N)」とする
- `N`、`Esc`、ダイアログの閉じる操作はキャンセルとして扱う
- `Y`または「続行」を明示的に選択した場合だけ走査を開始する
- 続行した場合も、進捗表示、キャンセル、安全上限、アクセス不能箇所の読み飛ばしを適用する

## 9. 起動対象と起動動作

### 9.1 基本方針

OpenGepaはWindows標準の方法で対象を開く。特殊な起動方法が必要な場合は、ユーザーがWindowsショートカットを作成し、その`.lnk`をFileItemとして登録する。

OpenGepaは次の設定を独自に持たない。

- 起動引数
- 作業ディレクトリ
- 管理者として実行
- PowerShell実行オプション
- コンソールウインドウの表示／非表示
- 環境変数
- 複数コマンドの組み立て
- Windows互換モード

### 9.2 FileItem

- 絶対ファイルパスを保持する
- ドライブ文字を持つ絶対パスまたはUNC絶対パスを許可する
- 相対パスを拒否する
- `C:Tools\App.exe`のようなドライブ相対パスを拒否する
- Windowsシェルまたは標準の関連付けを使用して開く
- `.lnk`内部のリンク先、引数、作業ディレクトリはWindowsに任せる
- `.lnk`内部のリンク先をOpenGepaが解析または補正しない
- `.ps1`はWindowsの標準関連付けに従う。PowerShellとしての実行が必要ならユーザーがショートカットを作成する

### 9.3 DirectoryItem

- ドライブ文字を持つローカル絶対パスを許可する
- UNCネットワークディレクトリを許可する
- 相対パスおよびドライブ相対パスを拒否する
- Windows Explorerで開く
- ドライブ補正の対象にしない

### 9.4 UrlItem

- `http`または`https`の絶対URLだけを許可する
- スキームを必須とする
- OpenGepaがスキームを自動補完しない
- Windows既定ブラウザで開く
- OpenGepa自身は接続確認を行わない

次の形式は拒否する。

- `file:`
- `javascript:`
- `data:`
- `shell:`
- `ftp:`
- 任意のカスタムURIスキーム
- スキームのない文字列
- ユーザー名またはパスワードを含むURL

ローカルまたはネットワーク上のファイルとディレクトリはURLとして扱わず、FileItemまたはDirectoryItemとして登録する。

### 9.5 起動成功

OpenGepaは、起動要求がWindowsに受理された時点を成功とみなす。対象アプリケーションまたはWebページの内部動作までは監視しない。

起動要求に成功した場合はランチャーウインドウを閉じる。

### 9.6 起動失敗

- OpenGepa本体を終了しない
- ランチャーウインドウを閉じない
- 項目名、対象、失敗理由を表示する
- 対象LauncherItemの編集画面を開けるようにする
- 技術的な詳細をコピーできるようにする
- 通常表示ではスタックトレースを直接表示しない

`.ogp`をLoadしただけでは、FileItem、DirectoryItem、UrlItemを一切起動しない。ユーザーが明示的に項目を選択した場合だけ起動する。

## 10. FileItemのドライブ補正

### 10.1 実行タイミング

ドライブ補正はOpenGepa起動時やアイコン表示時には行わない。ユーザーがFileItemを起動したとき、登録されたファイルが存在しない場合にだけ行う。

### 10.2 対象

- FileItemのみ
- ドライブ文字を持つ絶対パスのみ
- 元のファイルが存在しない場合のみ

次は対象外とする。

- Group
- DirectoryItem
- UrlItem
- UNCパス
- 相対パス
- ドライブ相対パス
- `.lnk`内部のリンク先

### 10.3 探索方法

- Windowsから固定ドライブとして認識されているドライブだけを対象とする
- CからZまでドライブ文字順に確認する
- リムーバブル、光学、ネットワーク、未準備のドライブは対象外とする
- 元のパスからドライブ文字だけを変更する
- 途中のディレクトリ名とファイル名は完全に同じ候補だけを確認する
- ディレクトリ全体の高度な検索は行わない
- アクセス拒否や確認時の例外は、そのドライブだけ読み飛ばす

例:

```text
登録: D:\Tools\App.exe

候補:
C:\Tools\App.exe
E:\Tools\App.exe
F:\Tools\App.exe
...
Z:\Tools\App.exe
```

### 10.4 発見時

- CからZの順で最初に見つかった候補を採用する
- それ以降のドライブは探索しない
- 候補をWindows標準の方法で起動する
- 起動要求が成功した場合だけFileItemのtargetを書き換えて即時保存する
- 補正成功をユーザーへ通知しない
- キャッシュ済みアイコンは自動変更しない

最初に見つかった候補の起動に失敗した場合は、targetを書き換えず、後続ドライブの候補も起動せず、通常の起動失敗として表示する。

この仕様は、同じ相対パスに別のファイルが存在する場合の誤修復可能性を許容する。補正直後に対象が起動されるため、意図と異なる対象であればユーザーが確認できることを前提とする。

## 11. アイコン管理

### 11.1 基本方針

- ユーザー指定画像と対象ファイルから自動取得したアイコンは、保存後は区別しない
- どちらもOpenGepa内へPNGとしてキャッシュする
- JSONにはアプリディレクトリからの相対パスだけを保存する
- 通常のランチャー表示では元のEXEやファイルへアクセスせず、キャッシュ済みPNGを使用する
- LauncherNodeの同一性は内部IDで管理し、アイコンファイル名を識別子として使用しない

JSON例:

```json
{
  "icon": "icon/Chrome_20260830_202804021.png"
}
```

### 11.2 表示時の順序

1. JSONで指定されたキャッシュ済みアイコン
2. 項目種類ごとのOpenGepa標準アイコン

FileItemの登録、編集、ディレクトリ一括登録の確定時には、対象からのアイコン取得を一度試みる。取得に失敗した場合はJSONのアイコンを未指定または`null`とし、OpenGepa内蔵の標準アイコンを表示する。

ランチャー表示時にはアイコンの自動抽出を行わない。キャッシュ済みアイコンの欠落時も標準アイコンを表示し、表示のたびに抽出を再試行しない。ユーザーが編集画面の「対象ファイルからアイコンを再取得」を選んだ場合だけ再試行する。アイコン取得だけを目的としたドライブ補正は行わない。

### 11.3 PNG変換

- 出力形式はPNGとする
- JPEGでは保持できない透明部分を維持するため、RGBAとして保存する
- 最大サイズは256×256ピクセルとする
- アスペクト比を維持する
- 正方形へ強制的に引き伸ばさない
- 元画像の透明部分を白または黒で塗り潰さない
- 256px未満の小さい画像は拡大せず、元の解像度のPNGとして保存する
- 256pxを超える画像だけを、アスペクト比を維持して縮小する
- 256pxの透明キャンバスへ中央配置するための余白は追加しない
- アニメーション画像を受け付ける場合は先頭フレームだけを使用する

v0.1で受け付けるユーザー指定画像形式は次のとおりとする。

- PNG
- JPEG
- BMP
- ICO

ICOに複数サイズが含まれる場合は、256×256への変換に最も適した画像を選択する。

### 11.4 ファイル名

形式:

```text
{正規化した項目名}_{yyyyMMdd}_{HHmmssfff}.png
```

例:

```text
Chrome_20260830_202804021.png
```

同名が存在する場合は連番を付ける。

```text
Chrome_20260830_202804021_2.png
Chrome_20260830_202804021_3.png
```

ファイル名生成規則:

- 表示名の前後の空白を除去する
- Windowsのファイル名に使用できない文字を`_`へ置換する
- 末尾の空白とピリオドを除去する
- 名前部分が空になった場合は`Icon`を使用する
- 名前部分が長すぎる場合は規定長で切る
- ローカル時刻を使用する
- ミリ秒を含める
- 衝突時は利用可能な最初の連番を付ける
- 排他的な新規作成を使用し、既存ファイルを上書きしない
- 項目名を変更しても既存アイコンファイルを改名しない

### 11.5 変更と再取得

編集画面では次を提供する。

- アイコンを変更
- 対象ファイルからアイコンを再取得
- 標準アイコンに戻す

新しいアイコンは別ファイルとして作成し、書き込みと検証に成功してからJSONの参照を変更する。既存アイコンを直接上書きしない。

ユーザー指定と自動取得を区別しないため、対象パスの変更、アプリ更新、ドライブ補正時にアイコンを自動更新しない。ユーザーが明示的に再取得した場合だけ変更する。

### 11.6 不要アイコンの整理

項目削除やアイコン変更と同時に古いファイルを削除しない。

少なくとも次のすべてから参照されていないことを確認した後にだけ削除できる。

- `opengepa.json`
- `opengepa.backup.json`
- `opengepa.lastgood.json`

`.ogp`は必要なアイコンをパッケージ内部へ複製するため、作成済みProfileはランタイムの`icon`ディレクトリに依存しない。

## 12. データ保存と自動復旧

### 12.1 保存場所

ポータブル運用のため、設定とアイコンをアプリケーションと同じディレクトリ内へ保存する。

```text
OpenGepa/
├ OpenGepa.exe
├ opengepa.json
├ opengepa.backup.json
├ opengepa.lastgood.json
└ icon/
```

- OpenGepaディレクトリを丸ごとコピーすれば設定ごと移行できる
- `Program Files`など、通常ユーザーが書き込めない場所への配置は対応外とする
- 起動時に保存先への書き込み可否を確認する
- 書き込めない場合は、保存不能のまま編集を許可せず、明確なエラーを表示する
- アプリ更新時に既存JSONと`icon`ディレクトリを上書きしない

### 12.2 ファイルの役割

- `opengepa.json`: 現在の最新データ
- `opengepa.backup.json`: 最新保存の直前にあったデータ
- `opengepa.lastgood.json`: OpenGepaが実際に正常起動できたデータ

`opengepa.json`は少なくとも次を保持する。

- `formatVersion`
- LauncherTab一覧
- 各LauncherTabの表示状態と表示順
- 最後に選択したLauncherTab ID
- 各LauncherTabのツリー構造
- 各LauncherNodeの内部ID、表示名、種類、順序、target、アイコン相対パス
- OpenGepa内部で永続化が必要な設定

### 12.3 通常保存

確定済み編集操作ごとに次の手順で保存する。

1. 変更後モデルを一時的に構築する
2. モデル全体を検証する
3. `opengepa.tmp`へJSONを書き込む
4. 書き込んだJSONを再度読み込み、構文と構造を検証する
5. 現在の`opengepa.json`を`opengepa.backup.json`として保持する
6. `opengepa.tmp`を`opengepa.json`へ原子的に置換する
7. 保存成功後に表示モデルへ反映する

通常保存時に`opengepa.lastgood.json`は変更しない。

初回保存時など、既存の`opengepa.json`がない場合は、検証済み一時ファイルを新しい`opengepa.json`として配置する。

### 12.4 起動時の読み込み

次の優先順位で候補を読み込む。

1. `opengepa.json`
2. `opengepa.backup.json`
3. `opengepa.lastgood.json`

候補ごとに次を検証する。

- JSON構文
- 対応するフォーマットバージョン
- 必須項目
- LauncherTabとLauncherNodeの種類
- IDの妥当性と重複
- 同一階層の名前重複
- Group親子関係の循環
- 表示順とツリーの構築
- targetとアイコンパスの型および形式

個別の対象ファイル、ディレクトリ、URL接続先、アイコンが現在利用できないことは、データ全体の読み込み失敗とはしない。

### 12.5 lastgoodの更新

読み込み候補からモデルとTreeViewを正常に構築し、アプリケーションの初期化まで成功した後に、そのデータを`opengepa.lastgood.json`へ安全にコピーする。

- 読み込み完了前にlastgoodを上書きしない
- 一時ファイルを経由して原子的に置換する
- backupまたはlastgoodから復旧した場合は、その事実をユーザーへ通知する
- 読み込みに失敗したファイルを自動削除しない

すべての候補を読み込めない場合は、既存ファイルを維持したままエラーを表示する。ユーザーが明示的に空データで開始するまで既存データを上書きしない。

### 12.6 初回起動

保存ファイルが一つもない場合はエラーにせず、既定LauncherTabを一つ持つ初期モデルを作成する。最初の確定操作時に`opengepa.json`を作成する。

## 13. OpenGepa Profile（Save／Load）

### 13.1 ファイル名と形式

Profileファイル名:

```text
OpenGepaProfile_{yyyyMMdd}_{HHmmssff}.ogp
```

例:

```text
OpenGepaProfile_20260830_20280421.ogp
```

`.ogp`の実体はZIPコンテナとする。

```text
OpenGepaProfile_20260830_20280421.ogp
├ manifest.json
├ settings.json
├ menus/
│  ├ launcher-development.json
│  └ launcher-ai.json
└ icons/
   ├ Chrome_20260830_202804021.png
   └ Visual Studio_20260830_203015042.png
```

### 13.2 manifest.json

少なくとも次を保持する。

```json
{
  "format": "OpenGepaProfile",
  "formatVersion": 1,
  "createdAt": "2026-08-30T20:28:04.210+09:00",
  "createdBy": "OpenGepa",
  "appVersion": "0.1.0"
}
```

### 13.3 settings.json

Profileとして移行可能な設定を保持する。

Windows自動起動の有効／無効は含めない。これはProfile設定ではなく、各PCに対するOS設定として扱う。

LauncherTabの表示／非表示、表示順、最後に選択したタブなど、ランチャー構成に属する状態は保存対象とする。

### 13.4 menusとicons

- `menus`には全LauncherTabとツリー構造を格納する
- `menus`内のJSONファイル名には表示名ではなくLauncherTabの内部IDを使用する
- `icons`にはProfileから参照されるアイコンだけを格納する
- Profile内部の参照はProfileルートからの相対パスとする
- Windowsメニューなど、移行先PCを正本とする将来データはProfileへ含めない

### 13.5 Save

1. 一時的な`.ogp.tmp`へZIPを作成する
2. manifest、settings、menus、参照中iconsを格納する
3. ZIPを再度開き、構造と内容を検証する
4. 検証成功後に正式な`.ogp`ファイル名へ変更する
5. 作成途中の不完全な`.ogp`を正式ファイルとして残さない

同名の`.ogp`がすでに存在する場合は既存ファイルを上書きせず、`_2`、`_3`のように利用可能な最初の連番を付け、排他的に新規作成する。

### 13.6 Load

- Loadは現在のLauncherTab、ツリー、アイコン、Profile対象設定を置き換える
- Loadは既存データとのマージを行わないため、現在データとLoad対象データの同名項目を衝突として扱わない
- 実行前に置き換え確認を表示する
- 既存データへ直接展開せず、一時ディレクトリへ展開する
- manifest、formatVersion、JSON、アイコン、参照関係を検証する
- ZIP内の絶対パス、`..`、重複パスなど危険なエントリを拒否する
- 検証成功後にだけ現在データへ反映する
- Load失敗時は現在データを変更しない
- Loadしただけでは登録項目を起動しない
- 実行可能ファイル、スクリプト、ショートカットを含むProfileについては、信頼できるProfileだけを使用するよう注意を表示する

Profile内アイコンをランタイムの`icon`ディレクトリへ取り込む場合は次のように処理する。

- 同名ファイルが存在せず、安全な相対パスなら新規作成する
- 同名ファイルが存在し、内容も同一なら既存ファイルを再利用してコピーを省略する
- 同名ファイルが存在するが内容が異なる場合は、既存ファイルを上書きまたは無視せず、連番付きの新しい名前で保存する
- 連番付きに変更した場合は、Load対象JSON内のアイコン相対パスも新しい名前へ書き換える
- すべてのコピー、書き換え、検証に成功するまで現在データへ反映しない

## 14. 設定ウインドウ

v0.1では次の設定を提供する。

### 14.1 一般

- Windows起動時にOpenGepaを起動する

自動起動は現在のPCだけに適用し、`.ogp`へ含めない。設定変更は即時反映・即時保存する。

自動起動には、現在ユーザーのStartupフォルダにある次のショートカットを使用する。

```text
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\OpenGepa.lnk
```

- 設定を有効にした場合は、現在の`OpenGepa.exe`を指すショートカットを作成する
- 設定を無効にした場合は、OpenGepaが管理するショートカットを削除する
- 管理者権限を要求しない
- OpenGepaを別ディレクトリへ移動後、ユーザーが新しい場所から手動起動した場合は、既存ショートカットが古いOpenGepaを指していれば現在位置へ修復する
- 同名であってもOpenGepaが管理していないショートカットを無条件に削除または上書きしない

### 14.2 タブ

全LauncherTabを一覧表示し、次を操作できる。

- 表示／非表示
- 表示順を上へ移動
- 表示順を下へ移動

上下操作の後も、移動したタブを選択・フォーカスした状態に維持する。先頭では「上へ」、末尾では「下へ」を無効化する。

非表示にしてもLauncherTabとツリーデータを削除しない。再表示時は以前のデータと表示順を維持する。

現在選択中のタブを非表示にした場合は、次の表示可能タブ、前の表示可能タブ、先頭の表示可能タブの順で選択する。表示中タブが一つもない場合は空状態を表示する。

最後の表示中App Launcherを非表示にしてもよい。空の縦タブ領域から設定または新規登録へ復帰できる。

### 14.3 外観

設定画面でテーマを`ライト`、`ダーク`、`カスタム`から選択できる。Windowsのシステムテーマへの自動追従はv0.1では行わない。

- ライトとダークは、ウインドウ、パネル、枠線、縦タブ、選択色を含む組み込み配色とする
- カスタムでは次の4色を`#RRGGBB`形式で設定できる
  - Group背景色
  - Group文字色
  - 項目背景色
  - 項目文字色
- DirectoryItemとUrlItemは項目配色を使用する
- GroupとLauncherItemの背景色は、ランチャー画面と編集TreeViewの両方で、インデント位置から右端の手前までの各行領域へ反映する。背景色のために横スクロールバーを発生させない
- App Launcherの縦タブは、左端の余白を設けない76×76のアイコン領域で構成する。表示名はアイコン領域の下部に半透明背景で重ね、下の画像を透過して見せる。アイコンを切り抜きして背景化しない
- App Launcher用に別の76×76 PNGを保存しない。共通のアイコンキャッシュは透過PNG・最大256pxの原画像を維持し、76×76表示用には152pxで読み込んで高品質補間する。76px未満の原画像は保存時に拡大しない
- `iconSet/appIcon1.png`、`appIcon2.png`のような正の連番PNGが存在する場合、個別アイコン未指定のApp Launcherは表示順に従って数字順の既存ファイルを循環利用する。欠番は詰めて扱い、個別アイコンへ変更したタブは`icon/<名前>_日時.png`を参照してこの規則より優先する
- `iconSet/OpenGepa.ico`が存在する場合は常駐アイコンとして使用する。ICOは複数のサイズ・色深度の画像を格納できる。設定画面から常駐アイコンを変更するとき、ICO入力はそのまま保存し、PNG/JPEG/BMP入力は元画像の解像度を超えない16〜256pxの複数フレームを持つICOへ変換する。同名ファイルが存在すれば置換確認を表示する
- 縦タブの項目コンテナは余白を持たず、76×76のアイコン領域と同じ幅にする。横スクロールバーを表示しない
- DirectoryItemはtargetのフルパスを表示し、標準表示ではExplorer風のフォルダアイコンを使用する
- Group、DirectoryItem、UrlItem、およびタスクトレイアイコンには設定画面で既定画像を指定できる。個別アイコンがある場合は個別アイコンを優先し、なければ種別の既定画像、さらに未指定なら組み込み標準アイコンを使用する
- URL追加時と手動の「サイトのアイコンを取得」では、HTTP/HTTPSの接続先の`/favicon.ico`を短時間・サイズ上限付きで取得してPNGキャッシュへ保存する。取得失敗は登録を失敗させず、後で再取得できる
- 不正な色コードは保存せず、`#RRGGBB`形式であることを示すエラーを表示する
- 設定確定後は直ちに保存し、表示中の画面へ反映する

JSON例:

```json
{
  "appearance": {
    "theme": "custom",
    "groupBackgroundColor": "#F1F5F9",
    "groupForegroundColor": "#101828",
    "launcherItemBackgroundColor": "#FFFFFF",
    "launcherItemForegroundColor": "#101828"
  }
}
```

### 14.4 項目の起動操作

FileItem、DirectoryItem、UrlItemごとに、シングルクリックまたはダブルクリックで起動するかを設定できる。変更は即時保存する。キーボードの`Enter`は設定に関係なく起動する。

### 14.5 Save／Load

設定ウインドウからOpenGepa ProfileのSaveとLoadを実行できる。

## 15. エラー処理と安全性

- 個別項目の失敗でOpenGepa全体を終了させない
- 保存、Load、起動、アイコン変換、ディレクトリ走査の例外をUIスレッドまで未処理で伝播させない
- ユーザー向け表示には対象と理由を簡潔に示す
- 技術的詳細をコピーできるようにする
- 外部Profileや外部ドロップの内容を自動実行しない
- ZIP展開時のパストラバーサルを防止する
- JSON内の相対アイコンパスがOpenGepaディレクトリ外を指さないよう検証する
- ファイル生成には排他的作成と一時ファイルを使用し、既存データを意図せず上書きしない
- 単一起動により、複数プロセスから同じデータを同時保存しない
