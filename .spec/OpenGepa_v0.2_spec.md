# OpenGepa v0.2 仕様書

## 1. 位置付け

本書はOpenGepa v0.2.0で追加する機能の正本である。v0.1で確定した基本仕様は、本書が明示して変更する箇所を除き継続する。

v0.2.0では、通常のアプリランチャーに加え、Windows環境から生成されるタブと、URLだけを扱うWeb専用タブを提供する。Windows固有のデータは移行データの正本にせず、現在のPC・現在のWindowsユーザーの状態を正本とする。

## 2. v0.2.0の範囲

v0.2.0で実装する機能は次のとおりとする。

- Windows Menuタブ
- ストアアプリタブ
- Web専用タブ
- Windows主要操作プリセットタブ
- 特殊タブに対応した設定ウインドウのタブ切替
- 通常アプリランチャーからのショートカット作成

起動履歴タブおよび使用頻度タブはv0.2.0へ含めない。

## 3. タブ種別

### 3.1 共通

LauncherTabは次の種別を持つ。

| 種別 | 正本 | 編集 | Profile |
|---|---|---|---|
| 通常アプリランチャー | OpenGepa | 可 | 含める |
| Web専用タブ | OpenGepa | 可。ただしURLとGroupだけ | 含める |
| Windows Menu | Windows Start Menu | 設定で明示的に有効化した現在のユーザー用／全ユーザー用だけ編集可 | 含めない |
| ストアアプリ | 現在のWindowsユーザーにインストールされたアプリ | 不可 | 含めない |
| 主要操作プリセット | OpenGepa内の固定カタログと現在のWindows環境 | 項目の表示／非表示だけ可 | 含めない |

Windows Menu、ストアアプリ、主要操作プリセットはシステムタブである。システムタブは名前変更、複製、削除を許可しない。設定画面では、通常アプリランチャー、Web専用タブを含む全タブについて、表示／非表示と表示順を変更できる。Web専用タブは通常アプリランチャーと同様に、名前変更、複製、削除も許可する。システムタブの表示状態と順序はローカルの`opengepa.json`へ保存し、Profileには含めない。

通常アプリランチャーおよびWeb専用タブのGroup、FileItem、UrlItemは、TreeViewで選択してF2キーまたは右クリックの［名前を変更］を選ぶと行内で名前を編集できる。Enterまたはフォーカス移動で確定し、Escで取り消す。DirectoryItemは表示名を持たないため対象外である。編集が許可されたWindows Menuのショートカットも同じ操作で改名でき、参照元に応じて通常のファイル操作またはUACを伴う限定ヘルパーを使う。

`iconSet`のタブアイコンは、通常アプリランチャーに`appIcon1.png`、`appIcon2.png`、…、Web専用タブに`urlIcon1.png`、`urlIcon2.png`、…を用いる。各系列は正の連番を数字順に循環利用する。Windows Menu、ストアアプリ、Windows主要操作はそれぞれ`winMenu.png`、`winStore.png`、`winCust.png`を用いる。個別に設定したタブアイコンがあれば、それを優先する。

### 3.2 タブごとの実行中状態

検索語およびTreeViewの展開状態はタブごとに保持する。保持期間はOpenGepaの実行中だけとし、JSONおよびProfileには保存しない。

選択中タブとピン止め状態のように連続して変わり得るローカル設定は、OpenGepa内の単一ライターキューで最後の状態だけを遅延保存する。タブ切替は保存完了を待たない。項目・タブの編集、Profile読込みなど、成功・失敗を操作結果として扱う変更は同じキューで順番を待ち、保存完了後に確定する。終了時は保留中の保存を完了させてから終了する。

OpenGepaを再起動した後、Windows Menuとストアアプリは全Groupを折り畳んだ状態から開始する。検索中に自動展開された状態は、検索を解除すると検索開始前の状態へ戻す。

## 4. 共通の検索とTreeView操作

通常アプリランチャー、Web専用タブ、Windows Menu、ストアアプリの上部には絞り込み用テキストフィールドを表示する。

| タブ | 検索対象 | 一致時の表示 |
|---|---|---|
| 通常アプリランチャー／Web専用タブ | 項目の表示名 | 一致項目と到達に必要な親Groupを表示する |
| Windows Menu | ショートカット名および配置フォルダ名 | 一致項目と到達に必要な親フォルダを表示する |
| ストアアプリ | アプリの表示名 | 一致項目を含む自動Groupだけを表示する |

検索中は一致項目を含むGroupを自動展開する。特殊タブのTreeViewの右クリックメニューには［すべて折りたたむ］を置く。大量の項目を一度に展開する［すべて展開］は設けない。

## 5. Windows Menuタブ

### 5.1 正本と表示

Windows Menuタブは、現在のユーザー用Start Menuと全ユーザー用Start Menuを正本として、フォルダ階層をTreeViewへ表示する。対象は`.lnk`とフォルダであり、フォルダは階層表示だけに用いる。`.url`など`.lnk`以外のファイルは表示しない。

Windows MenuのデータはOpenGepaへ保存せず、タブを開く時および利用者が［更新］を選んだ時に読み直す。OpenGepaから作成・削除を行った後も、直ちに読み直す。ファイル監視だけを正確性の根拠にしない。

### 5.2 編集の権限

設定ウインドウの［Windows機能］で、現在のユーザー用Start Menuおよび全ユーザー用Start Menuをそれぞれ編集可能に設定できる。初期値は両方ともOFFとし、OFFの正本は読み取り専用とする。

全ユーザー用Start Menuの作成、削除、名前変更などは書込み権限を必要とする。編集可能設定は権限を付与しないため、各変更操作ではWindowsのUACに従う。OpenGepa本体は常に非管理者として動作し、昇格するのは検証済みの全ユーザー用Start Menu配下に対する作成・削除・名前変更だけを行う限定ヘルパーとする。ヘルパーは任意コマンドまたは任意パスを受け付けない。UACを拒否した場合、または権限・ファイルシステム上の理由で失敗した場合、変更を適用しない。

### 5.3 重複と順序

現在のユーザー用と全ユーザー用に同名のフォルダがある場合は、同じGroupへ統合する。同じGroup内に同名のショートカットがある場合は、現在のユーザー用ショートカットをFileItemとして表示し、全ユーザー用の同名ショートカットは表示しない。

表示しているFileItemおよびGroupは、現在のユーザー用と全ユーザー用のどちらを参照しているかを内部的に保持する。これは名前変更、削除その他の編集操作で、正しいStart Menu実体だけを対象にするためである。

各Group内の基本順は文字コード順（ordinal）とし、利用者による並び替えは許可しない。設定ウインドウではフォルダを先に表示するか、ショートカットを先に表示するかを設定できる。これは種別間の優先順だけを変え、同種別内の文字コード順は変えない。

### 5.4 ショートカットの作成・削除

編集が許可されたStart Menuでは、通常のWindowsショートカットとして作成、編集、削除できる。ショートカット固有の対象、引数、作業ディレクトリ、アイコン、説明、ショートカットキー、表示方法および管理者実行は、Windows標準の`.lnk`プロパティに従う。OpenGepa固有の属性を追加しない。

削除前には、対象のStart Menu実体と表示名を明示して確認する。編集権限、参照元、UACおよび失敗時の不変更は5.2および5.3に従う。

## 6. ストアアプリタブ

### 6.1 正本と起動

ストアアプリタブは、現在のWindowsユーザーにインストールされているパッケージアプリを列挙する読み取り専用タブである。各アプリは検出時のAUMIDで起動し、絶対パスや表示名を起動識別子として保存しない。

表示対象は、現在のユーザーにインストールされ、FrameworkでもResourceでもなく、Start Menuへ公開される起動可能なアプリケーション（`AppListEntry`が`none`ではないもの）を持つパッケージとする。設定などWindows標準の利用者向けアプリも含める。フレームワーク、リソースパッケージ、Start Menuへ公開されない内部ホストその他の起動対象ではないパッケージは除外する。タブの一覧・Group・アイコンは環境から再生成し、JSONおよびProfileへ保存しない。

アプリ一覧はOpenGepaの実行中だけメモリにキャッシュする。初めてストアアプリタブを開く時に列挙し、以後のタブ切替・検索・表示ではキャッシュを使う。利用者がタブの右クリックメニューで［更新］を実行した時だけ、現在のWindows環境を再列挙してキャッシュを置き換える。

### 6.2 並び順と自動Group

アプリはWindowsの日本語照合順で表示名を並べる。OpenGepaは連続したアプリを自動Groupへ分割し、Group名を先頭および末尾アプリの先頭文字から生成する。

- 1 Groupは原則15件までとする。
- 15件に達した後も、次のアプリの先頭文字が直前のアプリと同じなら、同じGroupへ入れる。
- 現在のGroupが15件以上で、次のアプリの先頭文字が変わる直前に次のGroupを開始する。
- Group内の先頭文字が同じならGroup名は`M`のように一文字だけとする。異なるなら`A～M`のように表す。
- 英字、かな、漢字、数字、記号を同じ規則で扱う。表示名の先頭文字は、空白を除いた先頭の表示文字とする。

初回はすべての自動Groupを折り畳む。実行中に利用者が変更した展開状態は3.2に従って保持する。

## 7. Web専用タブ

Web専用タブはOpenGepaを正本とする、URLだけを登録できるタブである。HTTPまたはHTTPSのURLだけを登録でき、Groupによる任意深度の整理を許可する。FileItemおよびDirectoryItemは登録できない。

Web専用タブは通常アプリランチャーと同じ編集操作を持つ。ただし、追加・編集・外部ドロップ時にはURL制約を検証する。

主要ブラウザのブックマークImportおよびExportに対応する。対応ブラウザはMicrosoft Edge、Google Chrome、Mozilla Firefoxとする。ブラウザとのリアルタイム同期は行わない。ブラウザ側の区切り線は無視して取り込む。

Importでは、利用者が選択したブックマークHTMLファイルを読み込む。ブラウザプロファイルを直接読み取らず、HTMLに含まれるブックマークを範囲選択・プレビューなしで全件取り込む。Importごとに、ローカル日時の`yyyyMMdd_HHmmss`形式の最上位Groupを新しく作成し、その下へ展開する。同じ秒に複数回Importして名前が重複する場合だけ、最上位Group名へ`_1`、`_2`、…を付ける。

ブックマーク バー、その他のブックマーク、モバイルのブックマークなど、HTMLに含まれるルートを含め、フォルダ階層およびURLをWeb専用タブのGroup階層として保持する。既存Web専用タブとは統合しない。

`http`および`https`以外のURLは、Import全体のエラーにせずスキップする。取込み後はスキップ件数を表示し、利用者が選択した場合だけ表示名とURLの一覧を確認できる。HTTP(S) URLが一件もない場合は空の最上位Groupを作成しない。

Import後のUrlItemアイコンは、別の単一ワーカーで順に解決する。HTMLの`ICON`埋込み画像を最優先し、次に`ICON_URI`、最後に対象Webページからの既存サイトアイコン探索を用いる。ページHTMLを取得できなければ、自動探索はその時点で終了し、アイコン候補を推測して試行しない。HTMLを取得できた場合だけ、HTML内の`rel=icon`候補を試し、すべて失敗した時は`/favicon.ico`だけを省略時候補として試す。`/favicon.png`その他の推測候補は試さない。埋込み画像は全件を試みるが、Webアクセスを行う取得は1回のImportあたり先頭200 URLまでとする。Groupの［配下のサイトのアイコンを取得］は、配下を再帰的に走査し、個別アイコン未設定のUrlItemについて先頭200 URLまで同じキューへ入れる。既存の個別アイコンは上書きしない。同一URLは1回だけ取得し、成功結果を該当する全UrlItemへ反映する。UrlItemの右クリックメニューには［アイコンURLを指定して取得］を置く。HTTP(S)の絶対URLおよびブックマークURLを基準とする相対URLを受け付け、ページHTMLを取得せず指定URLだけを取得する。既存アイコンは成功時に置き換える。この項目はGroupメニューへ追加しない。アイコン取得中はTreeViewを再描画せず、成功結果が200件たまった時点、またはキューの処理完了時だけまとめて反映・再描画する。

ブラウザは同一フォルダ内の同名ブックマークまたは同名フォルダを許可するが、OpenGepaの同一Group内ではGroupとUrlItemをまたいで表示名を重複できない。この制約に当たるImport元の名前だけは、`_1`、`_2`、…を付けて自動改名する。既存Web専用タブとの名前およびURLの衝突解決は行わない。

不要な項目は、取込後に通常のWeb専用タブのGroupまたはUrlItemとしてDeleteキーで削除できる。削除時の確認は通常のGroupおよび項目削除規則に従う。

外部HTMLの取込はファイルサイズ16 MiB、ブックマークおよびGroupの合計100,000件、階層深さ256を上限とする。全体を一時モデルへ解析・検証し、成功した時だけ日時Groupを追加する。上限到達、構文不正、URL不正その他の失敗時は、既存データを変更せず日時Groupも残さない。

Web専用タブの右側縦タブの右クリックメニューには、ブックマークImportおよびExportを置く。Exportの保存先はWindowsの保存ダイアログで指定する。

Exportは、Microsoft Edge、Google Chrome、Mozilla FirefoxがImportできる共通のブックマークHTMLをUTF-8で出力する。ブラウザの内部プロファイルを直接書き換える独自形式は用いない。


## 8. 主要操作プリセットタブ

### 8.1 基本方針

主要操作プリセットは、Windowsの代表的な機能を開く固定カタログである。利用者は任意のコマンド、PowerShell、実行ファイル、引数を追加できない。独自の起動操作は通常アプリランチャーのFileItemまたはショートカットで扱う。

Group構成、Group名、Group順序、項目順序は固定とする。利用者は個々の項目を表示／非表示にでき、非表示にした項目は設定ウインドウから復活できる。空のGroupはランチャーへ表示しない。

主要操作プリセットの表示設定は`opengepa.json`に保存する現在の環境のローカル設定であり、Profileへ含めない。最初の作成時は、利用可能なプリセット項目をすべて表示する。

配布ZIPには、確定した初期表示状態を持つ`opengepa.default.json`を含める。起動時に`opengepa.json`が存在しない場合だけ、この初期テンプレートを元に初期保存データを作成する。既存の`opengepa.json`をテンプレートで上書きしない。

### 8.2 固定Group

カタログは少なくとも次の固定Groupを持つ。

| Group | 項目 |
|---|---|
| 基本操作 | 設定、検索、ファイル名を指定して実行、エクスプローラー、デスクトップ |
| ファイルと個人データ | ドキュメント、ピクチャ、ミュージック、最近使った項目、PC、エクスプローラーのオプション |
| アプリ | インストールされているアプリ、既定のアプリ、プログラムと機能、Windowsの機能、Microsoft Store |
| システムとデバイス | システム、システムのプロパティ、電源オプション、モビリティ センター、デバイス マネージャー、ディスクの管理、コンピューターの管理 |
| ネットワーク | ネットワーク接続、ネットワークと共有センター、インターネットのプロパティ、リモート デスクトップ接続 |
| 管理と診断 | イベント ビューアー、タスク マネージャー、ターミナル、ターミナル（管理者）、システム構成、サービス、タスク スケジューラ、リソース モニター、パフォーマンス モニター、証明書（現在のユーザー）、証明書（ローカル コンピューター）、ローカル グループ ポリシー エディター、レジストリ エディター |
| セキュリティと更新 | Windows セキュリティ、資格情報マネージャー、Windows Update、Windows Defender ファイアウォール（詳細設定） |
| 電源とセッション | ロック、サインアウト、スリープ、シャットダウン、再起動 |

Microsoft Storeを開く項目と、インストール済みストアアプリを列挙するストアアプリタブは別機能である。

### 8.3 環境依存の項目

NVIDIA Control Panelのように、対応するアプリまたは機能が存在する環境だけで利用可能な項目は、検出できる場合だけ表示する。利用できない環境では、ランチャーおよび設定カタログのどちらにも表示しない。

利用者が利用可能な項目を手動で非表示にした状態は保持する。後に環境が対応しても自動表示せず、設定カタログから明示して復活させる。

NVIDIA Control Panelは、実行ファイルの固定パスを使わず、検出したパッケージアプリのAUMIDを使って起動する。

### 8.4 実行の安全性

OpenGepaは各プリセットの既知のWindows機能だけを起動し、利用者入力をコマンド行として実行しない。

ターミナル（管理者）などの管理者操作はWindowsのUACに従う。ロック、スリープ、シャットダウン、再起動、サインアウトはOpenGepa側で操作内容を明示した確認を表示する。各項目の初期表示／初期非表示は実装前に別途確定する。

## 9. 設定ウインドウ

設定ウインドウは一画面の縦積みをやめ、上部のタブで複数画面を切り替える。少なくとも次の分類を設ける。

- 一般：Windows起動時の起動、ランチャーの基本動作
- ランチャー：通常／Webタブの表示と順序、項目のクリック操作
- 外観とアイコン：テーマ、配色、既定アイコン、トレイアイコン
- Windows機能：Windows Menu、ストアアプリ、主要操作プリセット
- データ：Profileの保存と読込、将来の履歴・使用頻度データの削除

［Windows機能］では、主要操作プリセットを固定Groupごとに表示し、利用可能な項目の表示／非表示と非表示項目の復活を行える。環境で利用できない項目は表示しない。

## 10. ショートカット作成

通常アプリランチャーから、作成後にFileItemとして登録されるWindowsショートカット（`.lnk`）を作成できるようにする。

ショートカットの詳細なプロパティはOpenGepa独自の編集ダイアログに複製せず、Windows標準の`.lnk`プロパティ画面を用いる。利用者はそこから対象、引数、作業ディレクトリ、アイコン、管理者実行などを設定する。

OpenGepaが作成する`.lnk`は、アプリケーションディレクトリ内の`shortcut/`へ保存する。これは`icon/`と同様にOpenGepaの管理領域とする。

FileItemを削除しても、OpenGepa管理の`.lnk`は`shortcut/`に残す。Profileを保存する時は、Profileから参照されるOpenGepa管理の`.lnk`をアイコンと同様に含める。Profile読込時は、これらの`.lnk`を`shortcut/`へ取り込み、読込後のFileItemが参照できるようにする。同名の既存`.lnk`があり内容も同一なら既存ファイルを再利用する。内容が異なる場合は既存ファイルを上書きせず、連番付きの新しい名前で保存し、読込対象のFileItem参照を新しい相対パスへ書き換える。すべてのコピー、書換え、検証に成功するまで現在データへ反映しない。

作成時の対象選択および作成後の標準プロパティ画面を常に開くかは実装前に別途確定する。

## 11. 保存とProfile

通常アプリランチャーおよびWeb専用タブのデータは従来どおりOpenGepaの保存データとProfileへ含める。OpenGepa管理ショートカットは、参照されるものだけをProfileへ含める。

Windows Menu、ストアアプリ、主要操作プリセットの生成データはProfileへ含めない。Windows Menuとストアアプリは移行先PC・現在のWindowsユーザーを正本とする。主要操作プリセットのカタログはOpenGepaのバージョンを正本とし、項目の表示／非表示設定だけを現在の環境のローカル設定として持つ。

- Windows Menu、ストアアプリ、Web専用タブ、主要操作プリセットを種別に応じた編集可否で表示・起動できる
- Windows Menuおよびストアアプリの検索、折り畳み、実行中だけの状態保持が仕様どおりに動作する
- Windows環境に存在しない環境依存プリセットを表示しない
- 主要操作プリセットの非表示と設定ウインドウからの復活ができる
- Profileが環境依存の特殊タブの生成データを含まない
- 通常アプリランチャーから作成したショートカットをFileItemとして登録できる
- 配布時の`opengepa.default.json`が既存の`opengepa.json`を上書きしない
- 新規・変更した規則に回帰テストを追加し、既存テストを含めて成功する
