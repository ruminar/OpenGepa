# OpenGepa v0.3.1 仕様

本書はOpenGepa v0.3.1で追加するWindows Menuショートカットのドラッグ＆ドロップ登録の正本である。v0.3.0までに確定した仕様は、本書が明示して変更する箇所を除き継続する。

## 1. Windows Menuショートカットの登録

Windows Menuタブに表示した`.lnk`ショートカットを、通常アプリランチャーの編集画面へドラッグ＆ドロップで登録できる。ランチャー画面のピン止め状態は、この操作の可否に影響しない。

ドロップ先は通常アプリランチャーだけとする。Webランチャー、Windows Menu、ストアアプリ、Windows主要操作、起動履歴、使用頻度は登録先にできない。

ドロップ先がGroupの中央ならそのGroup直下へ追加し、項目の上端または下端ならその項目の前後へ追加する。編集画面の空白へ落とした時はルート末尾へ追加する。

登録する項目は、Windows Menuの実行時項目を保存したり移動したりせず、新しいIDを持つ通常の`FileItem`として作る。`FileItem.Target`にはドラッグ開始時点の`.lnk`絶対パスを保存し、表示名には同時点のWindows Menu表示名を使う。登録後はWindows Menu側の改名、移動、削除と同期しない。

同じ親Groupに同名の項目がある場合は、既存の外部ドロップと同じく`_1`、`_2`の連番を付けて登録する。登録後は`.lnk`からアイコンを取得する。取得できない場合も登録自体は成功とし、既定のFileItemアイコンを表示する。

ドラッグ開始後は、元のWindows Menuショートカットを起動してはならない。ドロップ時にショートカットが存在しない、または有効な絶対`.lnk`パスではない場合は、登録せず警告を表示する。

## 2. 保存と互換性

作成した項目は既存の通常`FileItem`と同じ保存・Profile・起動規則に従う。保存形式、Profile形式、既存設定の移行規則は変更しない。

## 3. 完成条件

- ピン止めの有無にかかわらず、Windows Menuの`.lnk`を通常アプリランチャー編集画面へコピー登録できる
- 元のWindows Menu項目が変更されず、ドラッグ後に起動もしない
- Group内、行間、ルート末尾の各ドロップ位置で順序どおりに登録できる
- 同名、アイコン取得失敗、消失したショートカットを定めた規則で処理する
- 新規規則の回帰テストと既存テストが成功する
