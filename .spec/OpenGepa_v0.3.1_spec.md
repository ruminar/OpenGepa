# OpenGepa v0.3.1 仕様

本書はOpenGepa v0.3.1で追加するシステムタブおよび起動記録からのドラッグ＆ドロップ登録の正本である。v0.3.0までに確定した仕様は、本書が明示して変更する箇所を除き継続する。

## 1. システムタブ・起動記録からの登録

Windows Menu、ストアアプリ、起動履歴、使用頻度の各タブに表示した利用可能な項目を、通常アプリランチャーの編集画面へドラッグ＆ドロップで登録できる。ランチャー画面のピン止め状態は、この操作の可否に影響しない。利用不可の起動履歴項目は登録できない。

ドロップ先は通常アプリランチャーだけとする。Webランチャー、Windows Menu、ストアアプリ、Windows主要操作、起動履歴、使用頻度は登録先にできない。

ドロップ先がGroupの中央ならそのGroup直下へ追加し、項目の上端または下端ならその項目の前後へ追加する。編集画面の空白へ落とした時はルート末尾へ追加する。

Windows Menuの`.lnk`ショートカットは、新しいIDを持つ通常の`FileItem`として作る。`FileItem.Target`にはドラッグ開始時点の`.lnk`絶対パスを保存し、表示名には同時点のWindows Menu表示名を使う。登録後はWindows Menu側の改名、移動、削除と同期しない。

起動履歴・使用頻度から通常のFileItem、DirectoryItem、UrlItemを登録する時は、それぞれの起動先、表示名、設定済みアイコンを新しい通常項目へ複製する。履歴・頻度の表示用項目や起動記録データへの参照は保存しない。したがって起動履歴、使用頻度、または両方を削除・リセットした後も、登録済みの通常項目はリンク切れにならない。

ストアアプリを登録する時は、AUMIDを起動するOpenGepa管理の`.lnk`を`shortcut/`へ作り、その絶対パスを持つ通常の`FileItem`を作る。登録後はストアアプリ一覧や起動記録と同期しない。対象PCでそのAUMIDが利用できなくなった場合は、通常のFileItem起動の失敗として扱う。

同じ親Groupに同名の項目がある場合は、既存の外部ドロップと同じく`_1`、`_2`の連番を付けて登録する。登録後は`.lnk`からアイコンを取得する。取得できない場合も登録自体は成功とし、既定のFileItemアイコンを表示する。

ドラッグ開始後は、元の項目を起動してはならない。ドロップ時に通常ファイルまたはDirectoryの起動先が存在しない、または起動先情報が不正な場合は、登録せず警告を表示する。

## 2. 保存と互換性

作成した項目は既存の通常`FileItem`と同じ保存・Profile・起動規則に従う。保存形式、Profile形式、既存設定の移行規則は変更しない。

## 3. 完成条件

- ピン止めの有無にかかわらず、Windows Menu、ストアアプリ、起動履歴、使用頻度の利用可能な項目を通常アプリランチャー編集画面へコピー登録できる
- 元の項目、起動履歴、使用頻度が変更されず、ドラッグ後に起動もしない
- Group内、行間、ルート末尾の各ドロップ位置で順序どおりに登録できる
- 起動履歴・使用頻度を削除・リセットした後も、そこから登録した通常項目の起動先が維持される
- 同名、アイコン取得失敗、消失した起動先を定めた規則で処理する
- 新規規則の回帰テストと既存テストが成功する
