# OpenGepa v0.3 仕様書

## 1. 位置付け

本書はOpenGepa v0.3.0で追加または変更する機能の正本である。v0.1およびv0.2で確定した基本仕様は、本書が明示して変更する箇所を除き継続する。

v0.3.0は、利用者がランチャーを整理し、使った結果を次の起動に生かせるようにする版である。通常アプリランチャーおよびWeb専用タブには区切り線を追加し、OpenGepaから成功して起動した項目を一つの起動記録機構へ記録する。起動履歴タブと使用頻度タブは、その記録からそれぞれの目的に応じて表示する。

OpenGepaのUI、ダイアログ、設定、同梱文書は日本語のままとする。日本語／英語その他の言語切替はv0.3.0の対象外である。

## 2. v0.3.0の範囲

v0.3.0で実装する機能は次のとおりとする。

- 起動履歴タブ
- 使用頻度タブ
- 通常アプリランチャーおよびWeb専用タブのツリー内区切り線
- 起動履歴および使用頻度データの削除・リセット

右側縦タブに縦スクロールバーが必要な時は、ウインドウサイズを変えずに縦タブ列の幅を88pxから98pxへ広げる。スクロールバーが不要な時は88pxへ戻す。これにより、スクロールバーが表示されてもタブのアイコンと名前を隠さない。

設定ウインドウの［ランチャータブ設定］では、通常アプリランチャーおよびWeb専用タブを削除できる。システムタブは削除できない。削除前には、対象タブ内のすべてのGroup、項目、区切り線、およびタブ設定が削除され、復元できないことを確認ダイアログで明示する。

OpenGepaは、アプリケーション全体を対象とする汎用Undo／Redo機構を採用しない。利用者の操作を一律に履歴化して巻き戻すことよりも、複数の操作経路から設定・編集できること、削除前確認、失敗時の不変更、Profileの保存・読込などによって安全に編集できることを優先する。この方針はv0.3.0以降も継続する。将来、特定の操作に個別の取り消しが必要となった場合は、その操作の仕様で別途定める。

## 3. 起動記録

### 3.1 記録の契機

起動記録はOpenGepa内の単一の起動記録サービスだけが作成・更新する。各起動経路が独自に履歴または頻度を更新してはならない。

次の項目をOpenGepaから起動し、起動処理が成功を返した時に一件記録する。

- 通常アプリランチャーのFileItem、DirectoryItem、UrlItem
- Web専用タブのUrlItem
- Windows Menuのショートカット
- ストアアプリ
- `RecordLaunch`が`true`のWindows主要操作プリセット

ロック、サインアウト、スリープ、シャットダウン、再起動、およびメディア コントロール・音量操作は記録しない。Groupおよび区切り線は起動できず、記録もしない。

ここでいう成功は、OpenGepaがWindowsへ起動要求を受け渡せたことを指す。起動した外部アプリケーション、Webサイト、Windows機能が後から正常に利用できたことまでは判定しない。起動処理が失敗した場合、または利用者が項目を選択しただけの場合は記録しない。

記録対象の項目は、右クリックメニューの［起動記録に残さない］で除外できる。除外設定は識別子と、指定時の表示名を持つ。除外した項目の以後の成功起動は、起動履歴および使用頻度のいずれにも記録しない。除外を指定した時は、除外設定の追加、当該識別子に属する既存の履歴と使用頻度の削除を一回の原子的変更として行う。除外を解除した後は、その後の成功起動から新たに記録する。過去に削除した履歴・使用頻度は復元しない。

### 3.2 識別子と表示情報

起動記録は、対象を現在の項目へ解決するための識別子と、記録時点の表示名・アイコン・起動日時を持つ。

| 対象 | 識別子 |
|---|---|
| 通常アプリランチャー／Web専用タブ | LauncherNode ID |
| Windows Menu | Windows Menu内の相対パスと参照元 |
| ストアアプリ | AUMID |
| 記録対象の主要操作プリセット | 固定カタログのPreset ID |

通常アプリランチャーおよびWeb専用タブのLauncherNode IDは、全LauncherTabを通じて一意とする。親Groupまたは所属タブを変更してもIDは変更しない。Profile読込は通常／Webタブ全体を置き換えるため、Profile内で一意かつ正当なIDをそのまま使う。重複または不正なIDを含むProfileは読み込まない。

履歴または頻度から起動する時は、記録時の実行パス・URL・コマンドを再利用せず、識別子から現在の対象を解決して通常の起動処理を行う。これにより、通常アプリランチャーおよびWeb専用タブの項目の改名、所属タブまたは親Groupの変更、起動先修復、Windows環境の変化、主要操作カタログの変更に現在の起動処理を適用する。Windows Menuは相対パスと参照元で識別するため、ショートカットの名前変更または外部からの移動後は、過去の記録を解決できない場合がある。

現在の対象を解決できない記録は、起動履歴では最後に記録した名前とアイコンを使い「利用不可」と表示する。使用頻度では表示しない。記録自体は削除せず、対象が再び解決できる状態になった場合は再表示する。利用不可の履歴は起動できない。

同じ実行ファイル、ディレクトリまたはURLを複数のLauncherNodeとして登録した場合でも、それぞれの項目を別の識別子として履歴・頻度を記録する。使用頻度は起動先そのものではなく、OpenGepaのどの項目を利用したかを表す。Windows Menu、ストアアプリ、主要操作プリセットは、同じ相対パスと参照元、AUMID、Preset IDなら同じ対象として集計する。

### 3.3 保存と上限

起動履歴、使用頻度および除外設定は、現在のPC・現在のWindowsユーザーでだけ有効な一つの起動記録データである。`opengepa.usage.json`へ保存し、Profile、`opengepa.default.json`、配布物の初期データには含めない。`opengepa.usage.json`は`formatVersion` 1から開始する。

起動記録から除外する項目の識別子および指定時の表示名も、同じ起動記録データへ保存する。

起動履歴は新しい順に最大1,000件を保持する。上限を超えた時は最も古い履歴から削除する。使用頻度は保持中の履歴件数に左右されない。識別子ごとに、使用頻度を最後にリセットしてからの成功起動回数、最終起動日時、および直近30日を集計するための日別起動回数を保持する。日別起動回数は起動時点のローカル日付を`DateOnly`で記録し、表示時点のローカル日付から30日以上前となった値は削除する。

履歴への追加と使用頻度の加算は一つの保存単位として扱う。除外設定の追加・解除・既存記録の削除も同じ保存単位として扱う。保存に失敗した場合は、いずれか一部だけを永続化してはならない。通常の設定保存と同様に、単一ライターキューと原子的な置換を用いる。終了時は保留中の起動記録の保存を完了させる。

起動記録の保存失敗は、すでに成功した対象の起動結果を失敗へ変更しない。起動記録データの永続化だけを失敗として扱う。`opengepa.usage.json`を読み込めない場合も、OpenGepa本体の起動を阻害してはならない。その場合は履歴・使用頻度・除外設定を空の状態として扱い、以後の記録を新たに保存できるようにする。

## 4. 起動履歴タブ

起動履歴はシステムタブとして表示する。タブ名は「起動履歴」とし、名前変更、複製、削除、タブ内の履歴行の手動並び替え、外部ドラッグ＆ドロップを許可しない。右側縦タブ自体の表示順は既存の共通規則に従って変更できる。設定画面では、他のタブと同様に表示／非表示と表示順を変更できる。

履歴は新しい順に表示し、ローカル日付で「今日」「昨日」および年月日ごとのGroupへ分ける。起動日時はUTCの`DateTimeOffset`として保存し、日付Groupは保存せず、表示時点のローカル日時へ変換して再生成する。同じ日付Group内で同じ識別子を持つ起動記録は一行へ集約し、その日の最終起動時刻と起動回数を表示する。時刻欄と回数欄は右端の固定幅列として配置し、回数の桁数が増えても時刻欄の位置を変えない。各行は、現在解決できる場合は現在の項目名とアイコン、解決できない場合は最後に記録した項目名とアイコン、および「利用不可」を表示する。

履歴行は、現在の対象を解決できる時だけ通常のクリック、Enterキー、右クリックメニューの［起動］で起動できる。履歴タブの検索欄は現在解決できる項目名と、利用不可項目の最後に記録した名前を対象とする。検索、Groupの展開状態、右クリックの［すべて折りたたむ］は、既存のシステムタブの規則に従う。

## 5. 使用頻度タブ

使用頻度はシステムタブとして表示する。タブ名は「使用頻度」とし、名前変更、複製、削除、タブ内の使用頻度行の手動並び替え、外部ドラッグ＆ドロップを許可しない。右側縦タブ自体の表示順は既存の共通規則に従って変更できる。設定画面では、他のタブと同様に表示／非表示と表示順を変更できる。

使用頻度タブは、集計期間を［過去30日］および［全期間］から選べる。初期値は［過去30日］とする。選択した集計期間は現在のPC・現在のWindowsユーザーのローカル設定として保存し、Profileには含めない。

［過去30日］は、表示時点のローカル日付を含む直近30日間の日別起動回数を合計する。［全期間］は、使用頻度を最後にリセットしてからの成功起動回数を用いる。現在解決できる項目だけを、一つのフラットな一覧で表示する。［過去30日］では集計回数が1回以上の項目だけ、［全期間］では全期間の集計回数が1回以上の項目だけを表示する。表示順は選択中の集計回数の降順、同数の場合は最終起動日時の新しい順、さらに同一の場合は表示名の大文字・小文字を区別しない昇順とする。各行は項目名、アイコン、選択中の集計期間における起動回数を表示する。

使用頻度の各行は通常のクリック、Enterキー、右クリックメニューの［起動］で現在の対象を起動できる。起動すると、新しい履歴が追加され、当該項目の回数も一つ増える。使用頻度タブの検索欄は項目名を対象とする。

起動履歴タブは`iconSet/history.png`、使用頻度タブは`iconSet/frequency.png`をタブアイコンとして用いる。対応ファイルが存在しない場合は、既定のタブアイコンへフォールバックする。

## 6. 履歴・使用頻度データの削除

設定ウインドウの［データ］に、次の操作を置く。

- ［起動履歴を削除］: すべての履歴を削除する。使用頻度は変更しない。
- ［使用頻度をリセット］: すべての使用頻度を削除する。履歴は変更しない。
- ［起動履歴と使用頻度を削除］: 両方を削除する。

各操作は、削除対象と、元に戻せないことを明示した確認の後に実行する。確認を取り消した場合、または保存に失敗した場合、データと表示を変更してはならない。

履歴を削除した後も、以後の成功起動は新しい履歴として記録する。使用頻度をリセットした後は、全期間累計および日別起動回数を削除し、以後の成功起動から回数を数え直す。

［データ］には［起動記録の除外項目］も置く。ここでは、現在の対象を解決できる場合は現在の表示名とアイコン、解決できない場合は指定時の表示名、汎用アイコンおよび「利用不可」で一覧表示し、選択した項目の［除外を解除］を実行できる。対象を現在解決できない場合も、除外の解除はできる。設定画面で新たな項目を除外する操作は設けない。

## 7. ツリー内区切り線

### 7.1 データと配置

`SeparatorItem`は、通常アプリランチャーおよびWeb専用タブで使える正式なLauncherNodeである。表示名、起動先、アイコン、子要素を持たない。通常アプリランチャーとWeb専用タブのルートおよび任意のGroup配下へ置ける。Windows Menu、ストアアプリ、主要操作プリセット、起動履歴、使用頻度には置けない。

区切り線は親内で他のGroupおよび項目と同じ順序集合に含まれる。通常アプリランチャーおよびWeb専用タブは、ルートまたはGroupの右クリックメニューから［区切り線を追加］を選んで追加できる。複数の区切り線を同じ親内に置ける。表示名を持たないため、同名判定の対象にしない。

`SeparatorItem`は通常アプリランチャーおよびWeb専用タブの保存データとProfileに含める。既存の保存データと既存Profileは、区切り線がない状態のまま互換的に読み込む。

### 7.2 操作と表示

区切り線は、所属する階層のインデント位置からTreeViewの表示領域右端まで一本の線として表示する。高さ14pxのコンパクトなクリック領域を持つ。通常のランチャー画面では、区切り線への通常の左クリックおよび上下キー移動は選択状態を変更せず無視する。`Ctrl`を押しながら左クリックした時だけ、選択および同じ親内のドラッグ並び替えの対象とする。右クリックでは選択状態にかかわらず削除などのコンテキストメニューを開く。編集画面では通常の選択、親変更、削除を許可する。選択中は線を2pxとし、選択文字色で表示して見失わないようにする。クリック、ダブルクリック、Enterキーでは何も起動しない。名前変更、アイコン変更、既定アイコンへの復帰、サイトアイコン取得、ショートカット作成の対象にしない。

区切り線は選択、右クリック、削除、編集画面での親変更の対象にできる。削除時は、通常の項目削除と同じ確認規則に従う。通常アプリランチャーおよびWeb専用タブで`Ctrl`を押しながらドラッグする同じ親内の並び替えにも含める。検索語がある時は、区切り線を検索対象にせず表示しない。

ブックマークHTMLに含まれる`<HR>`要素は、その位置と所属フォルダを保持して`SeparatorItem`としてインポートする。`SeparatorItem`は外部HTMLの100,000項目上限に含める。UrlItemまたはSeparatorItemが一件以上ある場合に日時Groupを作成する。Web専用タブのルートまたは任意のGroupの右クリックメニューにある［📥 ブックマークをインポート］は、選択した取込先の直下へ日時Groupを作成し、その配下へHTML内容を取り込む。外部HTMLの構造を既存のツリーへ直接混在させない。Web専用タブをブックマークHTMLへエクスポートする時は、右側縦タブの［📤 ブックマークHTMLをエクスポート］からタブ全体を対象にし、`SeparatorItem`を`<HR>`として現在の順序位置に出力する。区切り線をサポートしないブラウザへインポートした場合、区切り線が無視されることがある。OpenGepaはそのために代替ブックマークや疑似項目を生成しない。

利用者が外部ファイルを明示的に入出力するメニューおよびボタンには、入力へ［📥］、出力へ［📤］を付ける。v0.3.0ではブックマークのインポート／エクスポート、およびProfileの読込／保存が対象である。通常の登録・変更操作および、利用者が選ばない内部データの自動保存・自動取得には付けない。

## 8. 既存データからの移行

`opengepa.json`の`formatVersion`は2から3へ更新する。v0.3.0は`formatVersion` 2の既存データを読み込み、区切り線を持たないデータとして移行できる。`formatVersion` 1の既存データは、従来のv0.2.0への移行を適用した後、同様に`formatVersion` 3へ移行する。v0.3.0で保存する`opengepa.json`は`formatVersion` 3とする。

Profileの`formatVersion`は1から2へ更新する。v0.3.0は`formatVersion` 1および2のProfileを読み込め、`SeparatorItem`を含めて保存するProfileは`formatVersion` 2とする。

v0.2.0以前の保存データに起動履歴タブおよび使用頻度タブの表示設定が存在しない場合、既存タブの表示順と表示状態を維持したまま、起動履歴タブ、使用頻度タブの順に末尾へ追加する。両タブの初期状態は表示とする。

## 9. 主要操作プリセットの起動記録

主要操作プリセットの固定カタログは、項目ごとに`RecordLaunch`を必須の`true`または`false`で持つ。既定値を設けず、新しいPresetを追加する時も必ず明示する。

次のPresetは`RecordLaunch`を`false`とする。

- デスクトップ
- ロック、サインアウト、スリープ、シャットダウン、再起動
- 前の曲、再生／一時停止、次の曲、停止
- 音量を下げる、音量を上げる、ミュート切替

上記以外のv0.2.0で定義した主要操作プリセットは`RecordLaunch`を`true`とする。

## 10. v0.3.0完成条件

- 日本語UIのまま、言語切替の設定・資源・英語文書を追加しない
- 一度の成功起動が、単一の起動記録処理を通じて履歴追加と使用頻度加算へ一回だけ反映される
- 失敗した起動、選択だけの操作、対象外の主要操作が履歴・使用頻度へ記録されない
- 右クリックで除外した項目は既存の履歴・使用頻度から削除され、以後は両方へ記録されない。設定画面から除外を解除した後は新しい成功起動だけを記録する
- 通常／Web項目は全タブで一意なLauncherNode IDを使い、親Groupまたは所属タブの変更後も履歴・使用頻度を継続する
- 履歴は新しい順に最大1,000件を表示し、頻度は履歴の上限と独立して［過去30日］および［全期間］で正しく集計される
- 使用頻度の初期表示は［過去30日］であり、選択した集計期間はProfileへ含めずにローカル保存される
- Windows Menuの改名または外部移動後に過去記録を解決できない場合は、履歴では利用不可として残り、頻度では非表示になる
- 起動済みの対象は、起動記録の保存に失敗しても失敗扱いにならず、履歴・使用頻度ファイルの読込失敗はOpenGepa本体の起動を妨げない
- 履歴の日付GroupはUTCで保存した日時を表示時のローカル日時へ変換して作る
- Profileおよび初期データが履歴・使用頻度を含まない
- 起動記録の除外設定がProfileおよび初期データへ含まれない
- `opengepa.json`をformatVersion 2から3へ、ProfileをformatVersion 1から2へ互換的に移行できる
- v0.2.0以前の保存データを、既存タブの順序を保ったまま表示状態がONの起動履歴・使用頻度タブへ移行できる
- 各削除・リセット操作が確認、原子的保存、失敗時不変更を満たす
- 通常アプリランチャーとWeb専用タブで区切り線を追加、移動、削除、保存、Profile移行できる
- 区切り線が検索、起動、Windows由来タブへ混入せず、Web専用タブのブックマークHTMLでは`<HR>`として順序と所属フォルダを保って入出力できる
- `<HR>`だけを含むブックマークHTMLも取り込め、区切り線を含む全項目数は100,000件以内に制限される
- 全Presetが明示したRecordLaunch値を持ち、RecordLaunchがfalseのPresetは起動記録へ追加されない
- 汎用Undo／Redoを追加しない
- 新規・変更した規則に回帰テストを追加し、既存テストを含めて成功する
