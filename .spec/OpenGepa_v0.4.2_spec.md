# OpenGepa v0.4.2 Windows Menuツリー展開状態

## 目的

Windows Menuを表示したまま通常ランチャーの編集画面へ項目を登録すると、データ更新によりWindows Menuツリーが再描画され、利用者が開いていたGroupが閉じる問題を解消する。

## 仕様

- 通常ランチャーまたはWebランチャーだけを変更する保存では、Windows Menu設定が変わらない限り、取得済みのWindows Menuランタイムツリーをそのまま引き継ぐ。Windows Menuの再取得やツリーの再構築は行わない。
- Windows Menuの表示設定を変更した保存では、取得済みランタイムツリーを引き継がず、次回表示時に再取得する。
- ［更新］、Start Menuショートカットの作成・改名・削除では、従来どおりWindows Menuを再取得する。
- 実際にWindows Menuを再描画する場合は、WPFのツリー項目コンテナが生成された後に、記録済みIDと一致するGroupを展開する。
- 親Groupを展開してから子Groupを順に復元し、任意の深さの展開状態を維持する。
- 利用者が明示的に［すべて折りたたむ］を実行した場合は、従来どおり全Groupを閉じる。

## 非変更範囲

- Windows Menuの取得、並び順、登録内容、起動、編集権限は変更しない。
- 展開状態はセッション中のUI状態であり、`opengepa.json`やProfileへ保存しない。

## 編集画面間のドラッグ＆ドロップ

- App Launcherの編集画面間では、通常のドラッグ＆ドロップは従来どおり移動とする。
- `Ctrl` を押しながら編集画面間でドラッグ＆ドロップした場合はコピーとする。コピー先には新しいIDを持つ独立した項目を作り、コピー元は変更しない。
- Groupをコピーする場合は配下を再帰的にコピーする。FileItem、DirectoryItem、UrlItem、説明、アイコン設定はコピーするが、起動先の実ファイルやアイコンファイル自体は複製しない。
- コピー先に同名のFileItem、UrlItem、Groupがある場合は、通常の登録と同様に末尾へ連番を付ける。DirectoryItemは同一Group内に同じ参照先を重複してコピーできない。
- `Shift` には操作を割り当てない。
- メイン画面の通常ランチャーから編集画面へドラッグ＆ドロップした場合は、修飾キーの有無にかかわらずコピーとする。元のメイン画面側の項目は変更せず、コピー先の編集画面だけを更新する。

## 右縦タブの空白地帯メニュー

- 右縦タブの項目以外の空白地帯を右クリックした場合は、ランチャー追加項目の後に［設定］と［このアプリについて］を表示する。
- ［このアプリについて］は実行中アセンブリのメジャー、マイナー、ビルド番号を `OpenGepa 0.4.2` の形式で表示する。
- 通常タブおよびシステムタブの既存コンテキストメニューには［設定］がすでにあるため、空白地帯の追加以外では変更しない。

## テスト

- Windows Menuを連続して読み込んでもGroupとショートカットのIDが安定する。
- 通常ランチャーへの登録などWindows Menu設定と無関係な保存後も、取得済みWindows Menuランタイムツリーの参照を維持する。
- Windows Menu設定を変更する保存後は、取得済みWindows Menuランタイムツリーを引き継がない。
- Windows Menuを再描画した際、記録済みの親子Groupを展開状態へ復元できる。
- 編集画面間でGroupを`Ctrl`ドラッグした場合、元のGroupと配下は残り、コピー先には新しいIDを持つ独立したGroupと配下が作られる。
- メイン画面の通常ランチャーから別ランチャーの編集画面へ登録しても、元のメイン画面の項目は残り、表示中ツリーを再描画しない。
- 空白地帯のコンテキストメニューには［設定］が一つだけ表示され、［このアプリについて］で3桁のアプリケーションバージョンを確認できる。
